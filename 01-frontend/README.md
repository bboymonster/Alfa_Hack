# 01. Frontend — интерфейс «Альфа-Бизнес»

Клиентское приложение сервиса **«Альфа-Инсайт»**: единая лента спаренных карточек
«Новость-Инсайт» с авторизацией, переключением роли и компании, интерактивным
диалогом с нейросетью и избранным.

## Стек

- React 19 + Vite 8 + Tailwind CSS 4;
- общение с backend через относительный путь `/api/*` (в Docker nginx проксирует
  на `backend:8000`, в dev-режиме — Vite proxy на `http://localhost:8000`).

## Запуск

```bash
npm ci
npm run dev          # http://localhost:3000 (прокси /api → localhost:8000)
npm run build        # сборка в dist/
npm run preview      # предпросмотр собранной версии
```

## Docker

Корневой `docker-compose.yml` собирает образ фронтенда (`Dockerfile`) и раздаёт
статику через nginx (`nginx.conf`) на порту `3000`, проксируя `/api` на backend.

## Автономный демо-режим

Если backend недоступен (например, на статическом GitHub Pages без сервера),
при сетевой ошибке или HTTP 5xx приложение переключается в демо-режим на встроенных данных
(`src/demoData.js`) — сценарий остаётся интерактивным: вход, смена компании и роли,
чат и избранное работают локально в браузере.

## Структура

```text
src/
├── App.jsx                # состояние: вход, лента, фильтры
├── api.js                 # API-клиент + переключение в демо-режим
├── demoData.js            # автономные демо-данные (зеркало backend)
└── components/
    ├── Login.jsx          # форма входа
    ├── Header.jsx         # селекторы компании/роли, избранное, выход
    └── NewsCard.jsx       # карточка «Новость-Инсайт» (6 вопросов, чат, избранное)
```

## Интерфейс и дизайн

- Светлая основа `#f5f5f7`, белые карточки, основной текст `#202124`, красный акцент
  `#ef3124`. Направление — [Альфа-Бизнес](https://alfabank.ru/corporate/rko/internet-bank/).
- Шрифт Golos Text хранится в `src/assets/fonts/` вместе с OFL-лицензией.
  Загрузка внешних шрифтов не требуется.
- Краткий инсайт до 210 символов и следующий шаг до 140. Это фрагмент полного
  текста, без отдельного LLM-вызова. Весь исходный анализ сохраняется в раскрытии.
- «Подробный анализ» — нативный `details`: доступен мышью, клавиатурой и на телефоне.
  Шаги обработки скрыты во вложенном раскрытии.
- Поиск и выбор темы фильтруют загруженную ленту; избранное сохраняется через API.
- Вход восстанавливается через `/api/auth/me`; устаревший JWT возвращает к форме.
- Демо-данные и результат LLM обозначаются отдельно.
- Состояния интерфейса: скелетоны карточек и счётчиков при загрузке, отдельные пустые
  состояния (нет карточек / ничего не найдено / избранное пусто) с действием, ошибка
  загрузки с кнопкой «Повторить» (при живой ленте — inline-алерт поверх карточек),
  тост внизу экрана для системных событий (истёкшая сессия, недоступный сервер).
- Ошибки API переводятся в понятные сообщения (`api.js`: сеть, таймаут, 5xx, 401/403/404);
  любой 401 централизованно завершает сессию. Запросы ограничены таймаутом
  (20 с лента/профиль, 125 с чат).
- Чат: автофокус и автопрокрутка, индикатор набора, Escape закрывает диалог,
  неудачный вопрос можно вернуть в поле одной кнопкой.
- Проверены ширины 320, 390, 768 и 1440 px, чат, фильтры, роль, компания и избранное.

Для статической сборки GitHub Pages workflow задаёт `VITE_DEMO_MODE=true`: она
работает без запросов к отсутствующему `/api`. В Docker эта переменная не задана,
используется реальный backend и серверный ключ LLM.

# 02. Backend — Серверный API и Бизнес-логика

## Зона ответственности
Разработка серверного API, системы аутентификации, выдачи объединенной ленты **«Новость-Инсайт»** с учетом контекста компании и роли пользователя, а также интеграции с базой данных и AI-сервисом.

---

## Архитектура API

### 1. Единый эндпоинт ленты «Новость-Инсайт»
Вместо раздельной выдачи сырых новостей и отдельных инсайтов бэкенд агрегирует и ранжирует пары **«Новость + Инсайт»** под конкретного клиента:

```http
GET /api/feed?company_id={SYNTHETIC_U}&role={CEO|CFO|ACCOUNTANT}&category={...}&page=1
```

Структура элемента ленты:

## Эндпоинты сервиса

| Метод | URL | Назначение |
|---|---|---|
| `POST` | `/api/auth/register` | Регистрация пользователя |
| `POST` | `/api/auth/login` | Вход, получение JWT токена |
| `GET` | `/api/auth/me` | Данные текущего пользователя и активная роль |
| `GET` | `/api/companies` | Список компаний-клиентов (для селектора профилей) |
| `GET` | `/api/feed` | Объединенная лента «Новость-Инсайт» с ранжированием |
| `GET` | `/api/feed/{id}` | Детальная карточка новость-инсайт |
| `POST` | `/api/feed/{id}/ask` | Интерактивный вопрос нейросети по новости |
| `POST` | `/api/feed/{id}/favorite` | Добавление/удаление из избранного |

## Требования безопасности из ТЗ кейса
- **Разграничение прав**: проверка JWT и изоляция данных по компаниям.
- **Журналирование вызовов AI**: аудит обращений к LLM, параметров генерации и времени ответа.
- **Маскирование чувствительных данных**: передача обезличенных идентификаторов (`SYNTHETIC_U`, `SYNTHETIC_F`).

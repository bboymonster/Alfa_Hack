# 03. Fullstack / Интегратор — API-шлюз, Трассировка, БД и Инфраструктура

## Зона ответственности
Связывание графового и ML-движка, агентной системы и пользовательского интерфейса в надежный, масштабируемый и воспроизводимый продукт.

---

## Ключевые задачи

### 1. Архитектура API и жесткие JSON-контракты
- Реализация единого backend-сервиса (FastAPI / Python) со спецификацией OpenAPI / Swagger.
- Разделение данных в структуре ответа на 4 независимых слоя:
  1. `facts`: подтвержденные факты из новостных источников.
  2. `alfa_insights`: цитаты и выдержки из официальных отчетов банка (с указанием файла и страницы).
  3. `company_context`: активированные признаки и метрики компании/контрагентов.
  4. `agent_verdict`: аналитический вывод, рекомендованные действия и контр-аргументы «Адвоката Дьявола».

### 2. Стриминг рассуждений агента (Трассируемость в реальном времени)
- Поддержка Server-Sent Events (SSE) / WebSocket для стриминга этапов работы мультиагентной системы:
  - Шаг 1: `[PLANNING]` — план действий.
  - Шаг 2: `[TOOL_CALL]` — обращение к графу связей / векторной базе отчетов.
  - Шаг 3: `[EVALUATION]` — сопоставление флагов компании с макропоказателями.
  - Шаг 4: `[DEVIL_ADVOCATE]` — проверка скептиком контр-сценариев.
  - Шаг 5: `[FINAL_VERDICT]` — итоговая карточка инсайта.

### 3. Интерактивный диалог и контекстные дозапросы
- Эндпоинты для чата внутри карточки риска/сделки:
  - Уточнение гипотез («Что если поставщик согласится на отсрочку 30 дней?»).
  - Пересчет финансового эффекта в рублях.
  - Запрос экспресс-аудита конкретного контрагента по ИНН / `SYNTHETIC_U`.

### 4. Демонстрационные профили клиентов
- Формирование 3–4 эталонных профилей компаний из разных отраслей:
  - Производственная компания с импортом и кредитами.
  - Локальный оптовик без импорта (для демонстрации Фичи №1 «Детектор блефа»).
  - Региональный дистрибьютор, готовый к экспансии (для Фичи №4 «Перехват контрактов»).
  - Компания со скрытыми аффилированными связями (Фичи №5 и №6).

### 5. Инфраструктура и упаковка (Production Ready)
- Сборка единого `docker-compose.yml` (Backend + Frontend + ML-движок + хранилище).
- Фиксация зависимостей (`requirements.txt` / `poetry.lock` / `pnpm-lock.yaml`).
- Оформление `THIRD_PARTY_NOTICES` с соблюдением требований лицензирования открытого ПО.
- Подготовка к развертыванию на внешнем демо-сервере.

# Принципы сервиса «Новость → Инсайт»

## Основные требования

### I. Контракт прежде всего
Границы сервиса описаны Pydantic-схемами и зафиксированы в `specs/*/contracts/`.
Публичный формат карточки `Insight`/`FeedItem` принадлежит `02-backend` и является
входом для AI-сервиса, а не наоборот: внутренняя модель «6 вопросов» (q1–q6) MUST
маппиться в него без потери полей. Изменение контракта MUST сопровождаться правкой
`contracts/` и согласованием с владельцем backend до реализации.

### II. Нет источника — нет утверждения
Поля «позиция Альфа-Банка», название отчёта, страница и ссылка MUST заполняться только
из фрагмента, найденного retrieval'ом в корпусе отчётов банка; при пустом или слабом
retrieval эти поля MUST быть `null`, а текст — явно сообщать об отсутствии данных.
Триггеры в `traceability.matched_company_features` MUST ссылаться только на реальные
поля профиля компании с их фактическими значениями. Шаг самопроверки MUST отбрасывать
или переписывать выводы, противоречащие профилю (например, импортные риски при
`FTS_FLAG = 0`). Выдумывать цифры, продукты банка и ссылки запрещено.

### III. Трассируемость и наблюдаемость
Каждый инсайт MUST содержать `traceability` (сработавшие признаки, использованные
источники, шаги агента, confidence). Каждый вызов LLM MUST писать structlog-событие
с `model`, `input_tokens`, `output_tokens`, `latency_ms`, `request_id`; сырые промпты,
ответы, PII и ключи на уровне `info` запрещены. Вызовы MUST иметь явные `timeout`,
`max_tokens`, `max_retries` с backoff; ошибка провайдера MUST превращаться в понятный
fallback, а не в 500.

### IV. Только разрешённые модели, провайдер через конфиг
В проде используются только LLM из Приложения 3 ТЗ (DeepSeek-V4.1-Flash, Qwen3.6 35B A3B,
GLM-5.3-Flash, Gemma 4 26B A4B, Kimi-K2.6, Qwen3-VL-30B-A3B-Instruct). Выбор провайдера,
`base_url` и id моделей MUST задаваться через pydantic-settings/env; хардкод id моделей
в коде запрещён. Код MUST работать без ключа: при его отсутствии включается
детерминированный offline-режим (fake LLM), помеченный `is_demo`/`mode` в ответе.
Тесты MUST использовать только fake LLM и не ходить в сеть.

### V. Тесты и eval как гейт
Новая логика MUST сопровождаться pytest-тестами (узлы графа, маппинг схем, retrieval,
HTTP-контракт); type hints обязательны, `ruff` и `mypy` чистые. Изменение промпта, модели,
параметров retrieval или корпуса MUST проходить eval (golden-набор карточек: recall
источников, покрытие 6 вопросов, отсутствие противоречий профилю) до мержа; регрессия
относительно baseline блокирует мерж.

### VI. Простота и независимость
AI-сервис — stateless HTTP-сервис: весь контекст компании и новости приходит в запросе,
собственное состояние — только индекс корпуса отчётов. Запрещено тянуть оркестраторы
очередей, внешние векторные SaaS и обучение моделей без отдельного решения. Любая новая
зависимость MUST быть оправдана в `plan.md` (Complexity Tracking).

## Технологические ограничения

- Python 3.12, зависимости только через `uv` (`pyproject.toml` + `uv.lock`) внутри
  `03-ai-service/`; остальные папки репо не трогаются без согласования.
- FastAPI + Pydantic v2 + pydantic-settings; async для I/O; structlog для логов.
- Агентная логика — LangGraph (StateGraph) с `RetryPolicy`, `recursion_limit`,
  structured output для всего, что парсится.
- RAG — Qdrant в embedded-режиме (`QdrantClient(path=...)`) и многоязычные эмбеддинги
  через FastEmbed; парсинг PDF — PyMuPDF с Tesseract OCR.
- Язык пользовательских текстов — русский; код, идентификаторы и коммиты — английский
  по конвенции репо; документация — русский.
- Данные кейса (PDF отчётов, CSV датасетов, индекс) не коммитятся; в репо — только
  `data/sample/` и инструкция по раскладке.
